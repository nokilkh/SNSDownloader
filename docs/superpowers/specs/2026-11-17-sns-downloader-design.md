# SNS Downloader design

Date: 2026-11-17, Asia/Hong_Kong. Requirements: REQUIREMENTS.md R001–R028. UI: docs/design/sns-downloader.svg (download overview), docs/design/post-detail.svg (reading layout), docs/design/library-layout.svg (latest platform/account/year/month/date navigation). Approved to start implementation on 2026-11-21. See PROGRESS.md for implemented behavior and validation limits.

## Intent and selected approach

Replace the Fanclub downloader with account-based X, Instagram and TikTok backup. Keep Electron/JavaScript, archive browsing, choosing local/mounted NAS folders, and copying/exporting downloaded items. Remove Fanclub login, token capture, categories and branding from the desktop product. Preserve existing archives; legacy formats remain readable through the existing reader where practical, without leaving Fanclub-specific controls in the new UI. Server deployment and server/NAS automation are outside this desktop change.

Approaches discussed:

1. **Selected by Boss:** retain Electron and integrate gallery-dl plus yt-dlp. Reuse maintained site extractors while maintaining our own archive contract, completion checks and readable UI.
2. Write three bespoke extractors: more control, substantially greater maintenance when sites change. Not selected.

## Content contract

- X (confirmed): only posts and replies authored by the target account, with text, images, videos and original image ALT. Exclude incoming replies, reposts, likes, bookmarks and standalone articles. A quote post authored by the target is treated as their post; do not recursively download the quoted author's post/media. Preserve parent/quoted IDs and links when available. Include text-only posts; identity filtering uses numeric author ID, not display name.
- Instagram: Stories and Highlights are confirmed. Ordinary posts, multi-image posts and Reels are proposed defaults. Preserve captions and per-media ordering. Store a Story once even if surfaced in multiple Highlights; preserve Highlight membership separately. Only currently accessible Stories/Highlights can be captured; no promise of recovering expired content. Live capture/recording is excluded.
- TikTok proposed defaults: the target's published videos and photo posts, captions and media ordering. Exclude likes, reposts, comments and live recordings.
- Default range (AI choice): all content the tool can enumerate now; do not imply a complete account history. Manual Update all is confirmed (R020); no scheduler or background monitoring. First backup defaults to all accessible content, with a Since date option (R014). AI date-boundary choice: selected day 00:00 inclusive, Asia/Hong_Kong, clearly labelled. A chronological cutoff must not stop at an old pinned post. Each run starts fresh and reads archive inventory solely to skip verified files; no automatic transaction/action replay or cross-run process resume.
- Highest resolution (confirmed R012): all media uses the largest accessible source resolution, no thumbnail downloads as final images and no artificial upscaling. X images request orig instead of timeline previews; inspect alternative available sizes including 4096x4096 where necessary and compare actual decoded dimensions. A size label is not proof of a 4096px file or that an original exists. Video format choice prioritizes resolution, then FPS/bitrate among comparable formats, with source audio retained. Use lossless merging/remux only as needed; do not force lossy codec conversions to fit MP4. Record selected format, actual final dimensions, quality check time and any fallback/unknown state. If original access fails, keep any useful lower-size file as explicitly degraded/partial, not full highest-quality success. Repeated runs skip verified highest-quality media; known lower-quality files can be upgraded by validating a temporary replacement before updating references, preserving the old file on failure. Tool metadata original_info may describe the source rather than the downloaded rendition: decode images/probe final videos for actual dimensions. Do not assume gallery-dl's highest-bitrate video variant is necessarily the highest resolution; compare resolved formats or delegate video format selection to yt-dlp.

## User flow and SVG

Use the existing three major destinations: Download, Library, Settings. Use exact #1E1E2E background, #CDD6F4 foreground and #FF007F accent, system font, restrained borders and rounded controls. Other colors are supporting choices. A 48px titlebar reserves left-side native window-control space. Maintain Traditional Chinese/Japanese language switching; new strings require translation parity.

Download: choose platform via segmented control, paste one or more profile URLs/usernames (one per line), see plain-language content scope, choose folder, then start. Account addition uses one platform at a time. The persistent account list shows platform, handle, last attempted time, last successful backup time and actual outcome. A row has Update; the user-triggered Update all queues saved accounts across platforms without duplicate execution. Auth-blocked accounts are reported individually while other accessible accounts may continue. Normalize account URLs, reject unsupported hosts and post URLs with an actionable message. Do not require users to choose extractor flags.

Access policy (R015/R021/R022/R029/R032/R033): try anonymous access first. Instagram and TikTok offer a platform-specific app login window with manual login and automatic cookie handoff for read-only validation. X opens Chrome on macOS, or the system browser elsewhere. macOS users can load a scoped Chrome extension once for a time-limited, encrypted local session handoff after pressing the X login button. X and Instagram accept a user-selected local cookie export via the native File menu. Each platform has one login identity which may authorize many target backup accounts. Cookie acquisition is distinct from verified access. Updates start only on manual request. Compatibility remains unproven until tested.

During work show the current account and phase, counts of saved/skipped/incomplete items, indeterminate enumeration where totals are unknown, plus pause/stop. “Pause” stops scheduling; in-flight files may finish and UI says so. “Stop” terminates child tools, settles writes and preserves verified files; no further work starts. Lock account, scope and folder changes while running. Anonymous access blocks pause the affected account and report access-required; offer the optional in-app login path; never require login for already accessible anonymous content. Transient retries are bounded; no blind endless retries or repeated authentication attempts.

Library: navigate platform → backed-up account ID → year → month → post date, with content/media filters as useful, and read entire posts inside the app. Keep index.md as the readable text artifact, as in the existing downloader. Show original link and timestamps (Hong Kong display, source timestamps retained). ALT capture, completeness reporting, revision comparison and repair apply only to X images. Instagram and TikTok still retain post text. X image ALT is selectable, labelled as original ALT, and associated with the correct image. Distinguish “未提供（來源明確回報）” from “未能取得” or “尚未檢查”. Do not invent ALT or use AI generated descriptions as backups. Preserve existing reader selection, refresh, paging and export functions. Existing code currently renders body as textContent and media separately; retaining index.md does not imply its existing media-first DOM order satisfies the newly requested reading order.

SVG includes the main download view and key state examples. All accounts, counts and statuses in the SVG are explicitly illustrative, not actual test results.

Latest user layout instruction supersedes the overview's compact side-by-side detail illustration: post text first, then media 1 followed immediately by its original ALT, then media 2 and its ALT, etc. Use a readable single column; preserve line breaks and emoji. Long ALT expands naturally rather than truncating to a one-line caption. Both the reader and readable exported post use this order. Missing ALT status stays with its image. See post-detail.svg.

User-supplied acceptance example: https://x.com/MomokoHashimoto/status/1828419307900149793. On 2026-11-17, read-only Chrome inspection opened the first image's ALT dialog and confirmed a multi-paragraph Japanese text containing event participation conditions. This is browser visibility evidence only, not gallery-dl extraction or archive validation. A second image and a quoted post are visible; do not mix their media/ALT or recursively capture quoted-account media. The example's authored text-only follow-up can also test reply inclusion. No full source text or media was copied into these mockups.

## Implementation boundaries

- Keep renderer/preload/main isolation and an explicit IPC allowlist. Renderer supplies validated form data, never arbitrary executable names/flags or filesystem paths for credential reads.
- Add platform adapter interface: enumerate(target, scope), normalize metadata, fetch media. gallery-dl handles platform enumeration/metadata and supported direct downloads; yt-dlp handles videos needing it. Choose one owner per media file; do not blindly run both. Inspect installed CLI output/options and upstream code before defining the adapter. Include text-only X posts explicitly; default gallery-dl media-only behavior is insufficient.
- Use spawn with shell:false, fixed flag construction and allowlisted URL hosts; keep subprocess progress machine readable. Track process handles and terminate process trees safely. Guard output paths against traversal; sanitize titles and treat captions/ALT as text, never trusted HTML.
- Archive schema v1 includes platform, stable account ID and current handle, post ID/kind/author ID, source URL/time, text, parent/quote reference, media stable ID/order/type, local relative path, expected size/hash when available, ALT status/value, and capture outcome/reason/time. Each post gets metadata.json and readable index.md plus media files. Never store cookies, authorization headers or raw signed URLs in archive metadata/logs.
- User-selected layout supersedes the earlier post-id directory proposal: root/{X,IG,TikTok}/account-id/YYYY/MM/date-folder/{index.md,media files,metadata.json}. There is no additional post-id directory under the date directory. AI naming choice: date-folder is YYYY-MM-DD_HHmmss__post-id in Asia/Hong_Kong, making same-day/same-second posts collision-free. Retain original source timestamp/timezone in metadata. Derive year and zero-padded month (01–12) from the same Hong Kong publication timestamp as the date folder, including month/year boundaries. If source date is unavailable, use unknown-year/unknown-month/unknown-date__post-id and surface the limitation. Visible account-id uses readable handle (e.g. MomokoHashimoto); numeric stable ID is authoritative metadata. Persist handle-to-ID mapping and keep the existing folder on a rename; a reused handle for a different stable ID gets a disambiguated folder, never a merge. Inventory rebuild uses metadata IDs, not names alone. Store Highlights as relationships rather than duplicated media. Use relative media links in index.md and metadata so moving the whole archive root preserves reading.
- index.md retains the existing readable header pattern (title, Sender, Date, source link), then post text followed by each image/video and its associated ALT. Preserve line breaks and escape untrusted markup; safe video rendering is generated by the app. Text-only posts still get a date folder and index.md. metadata.json is supporting data for identity/completeness, not a replacement for the user-requested readable Markdown. Media files live alongside index.md; this desktop export includes the user-requested year/month folders and no extra post-id directory below each date folder.
- Deduplicate by platform + original stable media ID where available; fallback post ID + deterministic attachment identity/order. Shared Story/Highlight media has one stored file plus relationships. Different IDs with identical bytes are not automatically declared the same source object.
- Download to .part; verify tool result, non-empty file and expected length where available, and appropriate image/video readability before atomic rename. Existing files only skip when inventory/path checks and recorded integrity pass; missing/corrupt media is fetched again. Existing archives without hashes are verified before adopting them. Atomic metadata writes; record per-media success independent of whole-post success. Source filtering, access errors and enumeration errors must not become “empty account” success.
- ALT/metadata acquisition has its own status and retry path. Existing media with missing ALT can fetch metadata only. An archive hit must not short-circuit metadata repair. Never erase a previously captured ALT just because a later response omits the field. Explicitly absent versus unavailable must be grounded in adapter evidence; omission alone means unknown.
- Manifest statuses: complete for the observed accessible item, partial, unavailable, failed, unsupported; report enumeration completeness separately. CLI exit 0 is insufficient. A run with missing data shows “部分完成”, affected counts/reasons and safe retry. Do not claim all historical content was backed up.
- Credentials: platform-specific cookies stored outside archives in userData, file mode 0600, encrypted at rest using Electron safeStorage where supported; refuse persistent plaintext fallback. Decrypt into private temporary files only for child tools, remove in finally and clean stale temp files on startup. Cookies imports validate domains, size and expired entries; no secret value in logs/errors. Run controls and content backups remain separate.
- New app product identity/data location should be SNS Downloader (AI choice); do not reuse old Fanclub tokens or automatically move old archives. Preserve old data and allow selecting it read-only. Packaging must include only runtime assets/tools and licenses, never user data.

## Independent builder review incorporated

- Resolve numeric account identity before writing archives. A reused handle must not merge different accounts; unavailable stable identity is an explicit limitation. Fallback attachment identities record provenance/stability and must not silently overwrite when attachment order changes.
- Application-level inventory controls skipping. Tool-level archive/early-abort options must not prevent metadata enumeration or ALT repair. Keep ALT observation time/status and retain known values when later responses omit them.
- Validate that the enumeration endpoint includes authored replies, not merely that author filtering works on the results it happened to return.
- Cookies parsing must support Netscape #HttpOnly_ lines and session expiry=0; filter irrelevant/expired entries without rejecting otherwise usable input. Temporary directories require private permissions/Windows ACLs as appropriate.
- Produce an installed-version/flags/JSON-field compatibility matrix during the spike. Hash and commit final post-processed videos, not intermediate fragments.
- Before removing shared desktop modules, inspect consumers. Reviewer found server/youtube_auth.py references src/main/utils/youtubeCookies.js; retain required validators and run affected server regression checks.

No additional user decisions arose from builder review; proposed defaults and the overall design/SVG remain awaiting approval.

Follow-up review of R010–R011 found no blocker. Normalize handle casing where platform rules allow, sanitize filesystem names and disambiguate suffix collisions. ## Confirmed management and archive refinements (R013–R020)

- Persist account preferences and result summaries outside credential storage; these are not automatic run-resumption checkpoints. Launching the app never starts a backup on its own.
- Custom root path is confirmed. Selecting a new root affects future output without moving/deleting the old root; Library can still select old sources.
- Keep local posts even if removed upstream. Absence in an incomplete enumeration or access failure is not proof of deletion; use unavailable/unknown unless an explicit source result supports deleted.
- Preserve observed text/ALT revisions before committing changed current content. Proposed per-post versions/<observation-id>/ contains previous index.md and structured metadata; media references may be shared, but exports must include referenced artifacts. Build revisions from normalized content; ignore counter changes. Metadata omissions never erase a previously known ALT. Avoid duplicating the same revision on repeated runs. Reader offers previous-version selection; latest/old-version controls are shown in post-detail.svg.
- Search saved post text and ALT, combine date/media/has-ALT filters, and label missing files and partial captures. Search spans selected platform/account scope including its year/month folders.
- Retry only failures, missing ALT and lower-quality media; refetch metadata when needed without downloading intact highest-quality media. Do not equate zero additional media transfers with zero HTTP metadata requests.
- Current SVG set covers management, per-account date ranges, search/filter, versions, login, path failures and user-triggered updates. The earlier single-platform download form is superseded by the account-list dashboard. SVGs are static proposals with illustrative values, not live data or verified platform capability.

Anonymous access evidence checked 2026-11-17: installed gallery-dl 1.32.12 and upstream Twitter extractor have authenticated-cookie requirements on some unauthenticated timeline errors; Instagram reels_media (used for Stories/Highlights) raises authenticated-cookie errors; TikTok has login-required branches. This establishes that universal anonymous support is unproven and can fail, not that every public URL requires login. No anonymous bulk live test has been run in this planning turn.

## Optional in-app browser login design and feasibility (R021)

User asks for an app-opened browser with manual login followed by automatic cookie capture. Selected default design: per-platform isolated Electron BrowserWindow session, no Node integration, context isolation and sandbox enabled, no privileged app IPC exposed to remote pages. Use a non-persistent partition and explicitly encrypted credential persistence to avoid an uncontrolled second plaintext cookie copy. Allow only required HTTPS platform/auth navigation; support expected login popups deliberately rather than granting arbitrary app privileges. Password, 2FA and challenges remain manual, and no password fields are read.

Observe navigation/cookie changes with bounded debounce; after candidate authenticated cookies appear, read only allowlisted platform cookies via webContents.session.cookies.get. Export a private temporary Netscape jar for gallery-dl/yt-dlp and perform a bounded read-only access check with the actual downloader. Distinguish “登入資料已取得” from “下載存取已驗證”. No raw cookies enter renderer, archive, logs or documentation. Maintain independent platform credential slots and clear/disconnect controls. Successful connection does not launch Update all; the user still triggers backups manually.

Existing main.js already opens a Fanclub BrowserWindow and captures an Authorization header, but uses a different token strategy and shared session. Only the window-shell pattern is reusable; do not retain that interception logic for SNS login. Electron official Cookies API supports reading session cookies including HttpOnly (https://www.electronjs.org/docs/latest/api/cookies); this proves API capability only. Whether each platform permits embedded-browser login and whether exported cookies suffice across the browser/CLI boundary must be tested, including IP/user-agent/session binding and login expiry. Opening the default external browser with shell.openExternal alone cannot deliver its cookies back to this app. R029 approves user-selected X and Instagram exports, using the same credential slots and access checks as in-app login.

## Accepted defaults and current SVG handoff (2026-11-17)

User: “預設跟你,之後補齊左svg先”. Accepted the six immediately preceding defaults and update-versus-retry distinction: one login identity per platform/many target accounts; per-account remembered range; latest-version default with historical text/ALT; removing a target keeps files and does not log out; inaccessible/full paths stop safely without automatic fallback; separate per-account counts and attempt/success timestamps. Requirements R022–R028 capture these decisions.

Layout plan: macOS tool window, 58px header with safe native-control inset, three top destinations (Backup accounts, Library, Settings). Palette tokens: background #1E1E2E, foreground #CDD6F4, accent #FF007F, sidebar/panel #181825, controls #313244, muted #A6ADC8. Positive #A6E3A1 and warning #F9E2AF have explicit text labels. System font throughout; labels 15px, helper 13px, titles 27px, path/IDs use system monospace where useful. Main account list is a compact row table; Library is a collapsible chronology tree beside a vertical reader. Avoid a metrics-first dashboard: put account actions and location before the result summary. Primary pink buttons use dark ink #11111B for contrast, with focus ring and separate selected/disabled states.

Six static screens, all with clear example-data notice:
- sns-downloader.svg: persistent multi-platform targets, one/all updates, range, location, last attempt vs success, completeness and six result categories, targeted retry.
- Account rows expose View results, populating a six-category summary for the selected account rather than substituting a global aggregate. Count units distinguish posts, media files and incomplete items. Retry is disabled when no known gaps exist.
- account-settings.svg: add/edit target, platform, remembered all/since range, inclusive Hong Kong boundary; removal confirmation retaining files and login.
- library-layout.svg: text/ALT search, date range, image/video filter, has-ALT filter, clear filters; platform/account/year/month/date hierarchy; source choice, paging and vertical reader preview.
- post-detail.svg: text then media then per-image ALT; latest-version control and history, old-version banner, missing ALT, lower-quality/unavailable explanations and copying/export actions.
- login-settings.svg: independent platform login slots, one login identity vs many targets, encrypted-credential handling, custom root; isolated website login + cookie-acquired/access-verified distinction and manual backup trigger.
- interaction-states.svg: empty, active enumeration, pause/stop, partial result, auth limitation, path/space failure, default/hover/pressed/focus/disabled controls.
- Paused and stopped are separate states. Resume is only available for a safely paused in-memory job; a fully stopped job offers return to account list and requires a fresh manual update, with normal archive deduplication.

Save/back actions are local preferences. “Update all” snapshots the saved target list and each target's range, runs serial account jobs without double-dispatch, and disables destructive edits/location changes until stopped. “Only retry gaps” operates on known incomplete items; metadata requests may still be needed. No auto scheduler, auto full update on login, or deletion implied by target removal. Version viewing never rewrites the remote website.

Static SVG is a review artifact, not an interactive prototype. Source account sample is illustrative, image slots are placeholders; dates used for revision history are observation times, not claims about source edit times. UI translations and responsive/minimum-width behavior are implementation acceptance tasks. The 1240px mockups define desktop layout; not evidence of responsive app behavior.
